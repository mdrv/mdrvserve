## v266.0.1 — Cross-platform binaries (macOS, Windows, ARMv7)

Expands release binary coverage from four Linux targets to eight targets
spanning Linux, macOS, and Windows.

### Added

- **macOS binaries** (`x86_64-apple-darwin`, `aarch64-apple-darwin`).
- **Windows binary** (`x86_64-pc-windows-msvc`).
- **ARMv7 Linux binary** (`armv7-unknown-linux-musleabihf`) for Raspberry Pi 2/3
  in 32-bit mode.
- **`install.sh` macOS support.** The installer now detects Darwin and maps to the
  correct Apple binary.

### Changed

- **README installation section** simplified: single `install.sh` curl command
  covers Linux and macOS. Homebrew instructions removed.
- **Release workflow** updated: cross-compilation for ARMv7 via
  `gcc-arm-linux-gnueabihf`, Windows builds on `windows-latest`, macOS builds on
  `macos-latest`.

### Install

```bash
# Linux or macOS — detects platform
curl -sSfL https://raw.githubusercontent.com/mdrv/mdrvserve/main/install.sh | bash

# From source
git clone https://github.com/mdrv/mdrvserve.git
cd mdrvserve && cargo build --release
```

Or download a binary from the
[latest release](https://github.com/mdrv/mdrvserve/releases/latest).

## v266.0.0 — Recursive serving, nav tree, refreshed docs & release pipeline

First release under the `mdrv` fork. mdrvserve is a markdown preview server built
as a companion for AI coding agents — render what an agent writes, live, in the
browser.

> [!CAUTION]
> mdrvserve is largely **LLM-assisted** code. It works and is tested, but has not
> been hand-audited like a traditional codebase. **Use at your own risk.**

### Added

- **`--recursive` (`-r`) directory mode.** `mdrvserve docs/ -r` scans nested
  subdirectories, serves every `.md`/`.markdown` beneath the root, and watches
  them recursively. Nested files are served at their relative path
  (`/guide/intro.md`) and appear as collapsible groups in the sidebar.
- **Relative-path file keys.** Tracked files are keyed by their path relative to
  the base directory, which doubles as the request URL. Flat directories keep
  the old filename-only keys (backward compatible).
- **Server-side navigation tree.** The sidebar is built server-side into a tree
  (`NavNode` → `build_sidebar_html`) and handed to the template as a pre-rendered
  `nav_html` fragment, with active-file highlighting baked in. No client-side
  tree logic.
- **Linux release binaries** for four targets:
  `x86_64-unknown-linux-gnu`, `x86_64-unknown-linux-musl`,
  `aarch64-unknown-linux-gnu`, `aarch64-unknown-linux-musl`.
- **Release-notes-driven releases.** Tagging `v*.*.*` builds the binaries and
  publishes a GitHub Release whose title and body come from
  `docs/releases/<tag>.md` (see `.github/workflows/release.yml`).
- **`install.sh` aarch64 support.** The installer maps Linux aarch64 to the
  `aarch64-unknown-linux-musl` binary.

### Changed

- **Docs rewritten** into a numbered, indexed set: `docs/README.md` (index) plus
  `00-overview`, `10-architecture`, `20-modes`, `30-cli-surface`, `40-rendering`,
  `99-known-issues`, and `guides/00-getting-started` + `guides/10-agent-integration`.
- **README** condensed; screenshots removed.
- **CI split.** `.github/workflows/ci.yml` is now pure verification (fmt, clippy,
  test, build) on push/PR. Releases are owned by `.github/workflows/release.yml`.

### Removed

- **macOS / Apple build targets** disabled (no prebuilt binaries for now).
- **crates.io publishing** removed — install via release binaries, `install.sh`,
  distro packages, or `cargo build --release` from source.
- Stale `docs/architecture.md`, the Contributing section, and in-repo PNG
  screenshots.

### Install

```bash
# Linux (x86_64 or aarch64) — detects platform
curl -sSfL https://raw.githubusercontent.com/mdrv/mdrvserve/main/install.sh | bash

# From source
git clone https://github.com/mdrv/mdrvserve.git
cd mdrvserve && cargo build --release
```

macOS users: build from source (`cargo install` / `cargo build --release`); no
prebuilt Apple binary is published this release.

### Known limitations

- Sidebar ordering is alphabetical only (no frontmatter `weight`).
- No search, no auth, no persistence — mdrvserve is ephemeral and localhost-first.
