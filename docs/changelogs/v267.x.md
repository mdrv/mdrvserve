## v267.4.0 — Structured logging, GFM alerts, and example docs

A batch release spanning observability, rendering, and learning material.

### Added

- **Structured logging (`--debug`/`-d`, `--trace`).** mdrvserve now emits
  `tracing` events instead of bare `println!`/`eprintln!`. `--debug` (or `-d`)
  sets the default level to DEBUG and `--trace` to TRACE; `RUST_LOG` overrides
  either when set. Events cover startup (served path, host, port, tracked file
  count, listening URL), each served request, the lazy-render cache (TRACE on
  cache hit, DEBUG on render), watcher events (TRACE), new-file tracking, and
  optional-binary warnings (missing `typst` / `d2` / typst HTML feature) plus
  the `open_browser` thread.
- **GitHub-flavored alert callouts (`--with-gfm`, alias `--gfm`).** Renders
  `> [!NOTE]`, `[!TIP]`, `[!IMPORTANT]`, `[!WARNING]`, and `[!CAUTION]`
  blockquotes into styled callout boxes with GitHub-matching hues. Implemented
  as an opt-in server-side post-processor (`render_gfm_alerts`); plain
  blockquotes pass through untouched. (markdown-rs's GFM parser covers tables,
  task lists, footnotes, etc., but not alerts, so this is a separate pass.)
- **`examples/` directory.** Five Japanese-language competitive-programming
  sample files — `markdown.md` (二分探索), `diagrams.md` (graph algorithms,
  exercising D2/LaTeX/Mermaid/Typst), `page.html` (a complexity cheat sheet),
  `document.typ` (a multi-page Segment-Tree lesson), and a `README.md` run
  guide — for trying every rendering engine end to end, including CJK text.

### Why

Logging makes the lazy-render pipeline from v267.3.0 observable: cache hits,
watch events, and startup are visible without recompiling. GFM alerts are the
most common markdown callout syntax and were the natural next rendering
affordance. The examples double as a manual test harness for every engine.

## v267.3.0 — Lazy rendering for faster startup

Directory-mode startup no longer renders every tracked file up front. Rendering
is deferred to first request, cutting boot time from roughly a minute (500+
markdown files) to a fraction of a second, while keeping serving entirely
from memory.

### Changed

- **Render on first request, not at boot.** `TrackedFile.html` is now
  `Option<String>`. Startup walks the directory and reads each file's source
  text — it does no rendering. The first `GET` of a file renders it (and, for
  `.typ`, both paged and free-flow forms) and caches the result; every later
  request is a pure `HashMap` lookup.
- **Invalidate on change.** The file watcher no longer re-renders eagerly. It
  re-reads the source and clears the cached HTML; the browser's WebSocket-
  triggered reload performs the re-render. Because the reload path already calls
  `window.location.reload()`, no frontend change was needed.
- **Single-user locking.** The new `ensure_rendered()` renders under the existing
  tokio state mutex. Render functions are synchronous and the server is
  single-user, so there is no deadlock risk and no double-render race.

### Why

A directory of 500+ markdown files took almost a minute to start because every
file was rendered eagerly. Lazy rendering preserves the zero-config default
(`mdrvserve dir/` just works) while making boot essentially free — only files
actually opened pay the render cost, and only once.

### Invariant change

The design constraint "Pre-rendered in memory. All tracked files are rendered
to HTML on startup and on change." becomes "Rendered on demand, served from
memory — rendered on first request and cached; invalidated on change. Serving
is always from memory." `AGENTS.md`, the overview, architecture, and rendering
docs were updated to match.

## v267.2.1 — Typst free-flow uses HTML export

The free-flow layout introduced in v267.2.0 re-compiled each `.typ` document
with `#set page(height: auto, fill: none)` and tried to recolour the resulting
paged SVG — an approach that did not yield usable output. It is replaced with
Typst's native HTML export.

### Changed

- **Free-flow now uses HTML export.** `.typ` documents are re-compiled with
  `typst compile - - --format html --features html`, producing reflowable
  semantic HTML (`<h2>`, `<p>`, `<ul>`, `<figure>`, …) with **native MathML**
  for equations. The emitted `<style>` is MathML-alignment CSS only — no
  colours, no fonts — so the output inherits the active theme: dark mode works
  and math glyphs follow the text colour.
- **Toggle disabled when unavailable.** A new `typst_html_available()` probe
  (OnceLock-cached) checks whether the installed `typst` binary supports
  `--features html`. When it does not, the free-flow button renders **disabled**
  with the tooltip "`typst` doesn't have HTML feature enabled"; there is no SVG
  fallback. Paged SVG rendering is unaffected.
- **Startup warning.** When Typst is requested but the installed binary lacks
  the HTML feature, `serve_markdown` logs a warning noting that free-flow is
  disabled and how to enable it (install a Typst built with `--features html`,
  0.13+).
- **Frontend.** `App.svelte` derives `freeflowAvailable` from a non-empty
  `contentFreeflow`; `TopControls.svelte` disables the button and swaps its
  tooltip when unavailable; `.typst-doc-freeflow` CSS is simplified to inherit
  theme colours and constrain inline media.

## v267.2.0 — Typst rendering with free-flow toggle

Adds Typst as a first-class rendering target alongside D2, Mermaid, and LaTeX.
Typst documents and fenced blocks are compiled **server-side** to SVG by shelling
out to the `typst` binary — matching the existing D2 model (no heavy in-process
crate, no client-side WASM). Pages are left white even in dark themes, since
Typst's paged model assumes paper. The `typst` binary is optional: if it is not
on `PATH`, a startup warning is printed and every Typst block or `.typ` file
degrades gracefully to an escaped source listing.

### Added

- **Typst fenced-block engine** (`--with-typst`). `` ```typst `` blocks inside
  `.md`/`.html` are rendered to SVG **server-side** via `typst compile - -
  --format svg` (stdin → stdout) and inlined as `typst-doc-page` containers. This
  mirrors `--with-d2` exactly: one compile per block, unique SVGs inlined into
  the stored HTML, no client JS, no render delay.
- **Standalone `.typ` file tracking** (`--include-typst`). Directory mode can now
  track `.typ` files alongside markdown and HTML. Each file is compiled through a
  temp directory using a `page-{0p}-of-{t}.svg` template, so **multi-page**
  documents render as a stack of `.typst-doc-page` SVGs separated by
  `.typst-page-break` rules. Independent of `--with-typst`: `.typ` rendering is
  gated by file extension, not by the block-engine flag.
- **Free-flow layout toggle.** On Typst-format source pages, a layout button
  (📄 paged / 📜 free-flow) appears as the leftmost control, to the left of the
  zoom slider. Paged is the default (stacked white pages). Free-flow re-compiles
  the document with `#set page(height: auto, fill: none)`, recolours every glyph
  from the baked `#000000` to `currentColor`, and renders a single transparent
  sheet that adopts the theme text colour and reflows to the content column.
  Both renderings are pre-computed server-side; the toggle switches between the
  two in-memory blobs with no extra compile. The choice persists across
  navigations via `localStorage`.

### Changed

- **Optional-binary pattern extended.** `typst_available()` mirrors
  `d2_available()` (OnceLock-cached `typst --version` check), and
  `serve_markdown` prints the same startup warning shape when Typst is requested
  but missing.
- **`tempfile` promoted** from a dev-dependency to a runtime dependency, since
  `render_typst_document` / `render_typst_document_freeflow` spin up a temp
  directory for multi-page compilation.

## v267.1.0 — HTML file support, sidebar filter, source view

### Added

- **HTML file support** (`--include-html`). Directory mode can now track
  `.html`/`.htm` files alongside markdown. HTML files skip markdown conversion
  but still get D2 and LaTeX post-processing — including VJudge-style
  `<span class="math math-inline">` patterns for competitive-programming
  solution pages. Single-file mode already accepted any file type; the flag
  gates directory scanning only.
- **Sidebar filter** with wildcard support. A funnel icon beside the sidebar
  toggle reveals a text input that filters the file tree live. Supports `*`
  and `?` glob patterns (e.g. `day4-*-id.md`). Directories collapse away when
  they contain no matches. The filter text and input visibility persist across
  page navigations. The funnel icon turns green when a filter is active.
- **Source view.** A clipboard button (📋) in the top-right control cluster
  opens a modal showing the raw source text of the current file, with a
  copy-to-clipboard button. Close with ESC, backdrop click, or ✕.

### Changed

- **Sidebar scroll persistence.** The sidebar scroll position is saved to
  `localStorage` on scroll and `pagehide`, and restored on mount — so
  navigating between files no longer resets the sidebar to the top.

## v267.0.0 — Svelte 5 frontend, opt-in D2/Mermaid/LaTeX, crates.io publishing

Major release: the MiniJinja template layer is replaced by a Svelte 5 + Vite
single-file bundle, diagram rendering becomes opt-in, and the crate is now
published to crates.io automatically on tag push.

> [!CAUTION]
> mdrvserve is largely **LLM-assisted** code. It works and is tested, but has not
> been hand-audited like a traditional codebase. **Use at your own risk.**

### Added

- **Svelte 5 frontend.** A Vite + Svelte 5 app builds to a single self-contained
  `frontend/dist/index.html` (JS and CSS inlined by `vite-plugin-singlefile`),
  embedded into the binary via `include_str!`. Server data — rendered HTML, nav
  tree, page title, diagram flags — is injected as a JSON blob at serve time
  through a placeholder token. The frontend hydrates from this blob; there is no
  client-side markdown parsing or fetch-based content loading.
- **D2 diagram support** (`--with-d2`). `` ```d2 `` fenced blocks are rendered to
  SVG **server-side** by shelling out to the `d2` binary at render time. The SVG
  is inlined into the stored HTML — no client JS, no render delay. Each diagram
  gets a unique `--salt` to avoid SVG element-ID collisions. Gracefully degrades
  to a plain code block if `d2` is not on `PATH`.
- **Opt-in Mermaid** (`--with-mermaid`). Mermaid is no longer always-on. Pass
  `--with-mermaid` to lazy-load the bundled `mermaid.min.js` for client-side
  rendering of `` ```mermaid `` blocks.
- **LaTeX math support** (`--with-latex`). Inline (`$...$`) and display
  (`$$...$$`) math expressions are rendered to SVG **server-side** via
  [RaTeX](https://crates.io/crates/ratex-svg) (v0.1.13, with embedded KaTeX
  glyph outlines). Each SVG's dimensions are computed from the viewBox so
  expressions scale naturally with surrounding text and the text-zoom slider.
  Dark themes apply `filter: invert(1)` to the black glyphs. No client JS,
  no external fonts.
- **Text zoom slider** (50%–150%) in the top-right control cluster. Scales text
  only; the content width stays fixed at 900px.
- **Collapsed sidebar circle navigation.** When the sidebar is collapsed, files
  appear as compact circle buttons with 2-character abbreviations (e.g.
  `GettingStarted` → `GS`) instead of hiding entirely.
- **crates.io publishing** via `.github/workflows/publish.yml`. Tagging
  `v*.*.*` verifies the tag matches the `Cargo.toml` version, then runs
  `cargo publish --locked`.
- **justfile** with bun/npm auto-detection and recipes for frontend build, check,
  and full cargo build.

### Changed

- **MiniJinja → Svelte 5.** The `minijinja` and `minijinja-embed` dependencies
  are removed. `templates/main.html` is deleted. The navigation tree is now
  serialized as JSON `navItems` (tagged-enum `NavNode` with `type`, `name`,
  `fullPath`, `abbr`, `children`) and rendered client-side by the recursive
  Svelte `SidebarList` component.
- **Dependency upgrades.** axum 0.7 → 0.8.9 (route syntax `{*filename}`,
  `Message::Text` takes `Utf8Bytes`), tower-http 0.6 → 0.7.0, axum-test 16 → 21
  (`TestServer::new` returns `TestServer` directly), clap 4.5 → 4.6.1, tokio
  1.0 → 1.52.3, serde 1.0 → 1.0.228, serde_json 1.0 → 1.0.150, anyhow 1.0 →
  1.0.103. Added `regex` for D2/LaTeX block detection, `ratex-*` for math.
  `Message::Text` takes `Utf8Bytes`), tower-http 0.6 → 0.7.0, axum-test 16 → 21
  (`TestServer::new` returns `TestServer` directly), clap 4.5 → 4.6.1, tokio
  1.0 → 1.52.3, serde 1.0 → 1.0.228, serde_json 1.0 → 1.0.150, anyhow 1.0 →

- **Width overflow fix.** In directory mode, long `<pre>` lines no longer widen

- **Docs rewritten** for the Svelte frontend, opt-in diagrams, and JSON data
